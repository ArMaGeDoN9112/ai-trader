# Jev для привязки публикаций к компаниям

Проверено 2026-11-06. Только первичные источники; интеграция не выбрана.

**Вывод:** кандидат для быстрой оценки подготовленных пар «публикация — компания». Открытый поиск причинных цепочек и свободное объяснение связи этим контрактом не закрываются. Это инженерный вывод из ограничений ниже; архитектура должна сохранять заменяемость модели.

## Документированные возможности

System One — класс моделей TypeSafe; Jev — первая публичная модель этого класса, TypeSafe предоставляет API. Это не бенчмарк и не готовый агент. Возвращает типизированные решения вместо генерируемого текста, не пишет объяснения рассуждений. Калибровка не гарантирует правильности отдельного ответа. [System One](https://docs.typesafe.ai/concepts/system-one)

Вход: `model`, `state` (строка/объект/массив JSON), именованные `questions`. Все вопросы независимо видят одно состояние. Факты и каталог передаёт приложение; веб-поиск и чтение Telegram этим API не документированы. [State](https://docs.typesafe.ai/concepts/state), [API](https://docs.typesafe.ai/api/system-one)

| Примитив | Выход |
| --- | --- |
| Noul | Вероятность «да» 0–1; без отдельного confidence |
| Choice | Один заданный вариант, распределение, confidence |
| Score | Оценка по описанным уровням, распределение, confidence; до 10 уровней |
| Box | Прямоугольник на изображении; здесь не нужен |

Источники: [Noul](https://docs.typesafe.ai/primitives/noul), [Choice](https://docs.typesafe.ai/primitives/choice), [Score](https://docs.typesafe.ai/primitives/score), [Introduction](https://docs.typesafe.ai/introduction).

Инструкции и варианты задаются в запросе; их можно строить из актуального каталога. Choice допускает до 255 вариантов; сумма вероятностей — 1. Это многоклассовый выбор, а не независимые вероятности влияния на компании. Для нескольких компаний — независимые Noul/Score и сбор списка кодом. Multi-label — композиция вопросов; компания вне переданных вариантов не появится в Choice. [Choice](https://docs.typesafe.ai/primitives/choice)

Многие вопросы оцениваются параллельно; по документации, добавление обычно мало меняет задержку. Это не гарантия постоянного времени для любого каталога. [Fan-out](https://docs.typesafe.ai/patterns/fan-out)

## Соответствие задаче

Нулевой результат нужно разрешить явно. Документация предлагает `none` или companion Noul «подходит ли вообще какой-либо вариант» и предупреждает, что `none` может работать плохо. Инженерный вариант: независимая проверка достаточности основания на компанию; пустой список, если никто не прошёл. Порог требует проверки на наших данных. [Choice](https://docs.typesafe.ai/primitives/choice)

Рекомендуемая схема приложения: ID компании, `direct`/`inferred`, ID публикации, точные фрагменты и факты о компании с источниками, основание. Это наша схема. Jev может выбрать ID заранее подготовленных доказательств; текстовое объяснение создаёт другой компонент. Официальный пример сначала находит допустимые фрагменты кодом, затем Jev выбирает один, приложение копирует текст. [Extraction cookbook](https://docs.typesafe.ai/cookbooks/pre_parsed_value_extraction_cookbook)

**Косвенное влияние — главный риск:** поставщик признаёт ухудшение многошаговых выводов, буквальное чтение, context rot, влияние порядка вариантов и уязвимость к враждебному содержимому state. Следовательно, цепочку «регулирование → отрасль → компания» нельзя считать доказанно решённой. [Model jaggedness](https://docs.typesafe.ai/model-jaggedness)

Инженерная рекомендация: отдельный компонент готовит события, кандидатов и подтверждённые зависимости; Jev оценивает пары; reasoning-модель разбирает сложные основания. Малый каталог можно оценивать целиком. Отбор большого каталога должен учитывать отрасли/сырьё/регулирование, иначе потеряет связи без упоминаний. Официальный пример разделяет retrieval, Jev и генерацию другим LLM, но не проверяет финансовые новости. [RAG cookbook](https://docs.typesafe.ai/cookbooks/classifying_rag_passages)

«Без галлюцинаций» в статье обосновывается совпадением схемы/ограничением ответов, а не истинностью связи. Confidence Choice/Score — концентрация распределения, не независимое доказательство правильности и не вероятность выбранного ответа. [Статья](https://typesafe.ai/blog/introducing-system-one-models-and-jev), [Confidence](https://docs.typesafe.ai/confidence)

## Версии, язык, скорость, доступ

Актуальны `jev-1.14.0` и `jev-1.13.0`; 1.14 вышла 14 октября. Текст и изображения; Box с 1.14. Контекст: 64k на запрос / 32k state+вопрос; отдельного лимита числа вопросов нет. Опциональные 262k медленнее и менее точны. [Models](https://docs.typesafe.ai/models)

Релиз 1.14 заявляет улучшение multilingual support. В просмотренных материалах не найдено списка языков, отдельного подтверждения русского или русского финансового eval. Это отсутствие подтверждения нашей задачи, а не доказательство отсутствия понимания русского. Изображения/long context экспериментальны. [Релиз](https://typesafe.ai/blog/jev-1-14)

Статья заявляет 70–500 мс end-to-end, ускорение 40–200× для подходящих задач. Измерения обычно делались с западного побережья США рядом с сервисом; короткий вход демо давал преимущество. 193.6× относится к авторским workflow-evals и названо верхней частью ожидаемых выигрышей. Это не SLA нашей цепочки. [Статья](https://typesafe.ai/blog/introducing-system-one-models-and-jev)

Workflow-evals: четыре задачи автоматизации; эталон — среднее ответов GPT-6 Astra и Claude Fable 5.1 с high thinking. Это консенсус моделей, не истина о влиянии новостей. [Методика](https://evals.typesafe.ai/)

Hosted API: `POST https://api.typesafe.ai/v1/systemone`, Bearer key из консоли, Playground; Python и JavaScript/TypeScript SDK. Доступ аккаунту не проверялся. Rate limits, перегрузка и retries влияют на задержку. [API](https://docs.typesafe.ai/api/system-one), [SDK](https://docs.typesafe.ai/sdk), [Ошибки](https://docs.typesafe.ai/api/errors)

Открытые веса Jev и инструкции self-hosting в просмотренных источниках не найдены. Открытый adapter вызывает другие LLM для сравнения, не запускает Jev локально; отдельные договорённости с поставщиком не исследованы. [TypeSafe adapter](https://github.com/typesafe-ai/system-one-adapter-python)

Следующий эксперимент: размеченные русские публикации с несколькими компаниями, пустыми совпадениями и косвенными связями; измерить полноту, ложные привязки, отказ, подтверждаемость оснований, p50/p95 на реальном каталоге. Это рекомендация, не выполненный тест.

Привязка пополняет новостной контекст; последующие агенты по новым публикациям учитывают рынок/позицию. Она не является торговым предложением или заявкой. Обязательные лимиты риска проверяются независимо; автоматическая ротация инструментов не входит в первую версию.

Запросы к Jev не запускались, аккаунты не подключались, сделок не было. Риск: качество русских косвенных привязок и задержка нашей задачи пока не измерены.
