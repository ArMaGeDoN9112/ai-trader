# Категории для всего каталога фьючерсов

Status: needs-triage

## Цель

Анализ новостей должен охватывать все фьючерсы из каталога брокера. Первый шаг — получить каталог фьючерсов и распределить их по категориям базовых активов. Текущая диагностика собирает каталог акций и проверяет один указанный фьючерс на акцию. Общий каталог фьючерсов нужен отдельно.

## Первый шаг

- Сгруппировать фьючерсы по базовым активам. Контракты на один базовый актив с разными сроками экспирации хранятся в одной группе с собственными идентификаторами контрактов.
- Для акций использовать отрасли, например финансы, нефтегаз и металлургию. Для остальных базовых активов начать с валют, индексов и сырья. Уточнить состав категорий по данным каталога брокера. Один базовый актив может входить в несколько категорий.
- Хранить соответствия в проверяемом справочнике. В отчёте показывать количество контрактов и базовых активов по категориям и явно перечислять позиции, которым категория ещё не назначена.

## Выгрузка и обновление каталога

Обработчик обновляет `groups.md` и `catalog.json` в `<data_dir>/futures-catalog` при запуске и каждые 24 часа работы. В обоих файлах остаются только контракты с флагом доступности через API. При ошибке чтения сохраняется предыдущая успешная выгрузка. Тот же каталог можно обновить вручную командой `futures-catalog`.

```powershell
.venv\Scripts\python.exe -m news_futures futures-catalog .local/runtime/futures-catalog
```

При необходимости передайте `--ca-file` с тем же PEM-файлом, который используется для диагностики песочницы.


## Подключение маршрутизации после проверки каталога

- На первом этапе модель выбирает ноль, одну или несколько известных категорий. Приложение проверяет идентификаторы и собирает кандидатов из справочника. Явно упомянутые базовые активы и базовый актив открытой позиции добавляются к кандидатам независимо от выбранных категорий.
- На втором этапе модель проверяет конкретную связь публикации с каждым базовым активом из списка. Результат может содержать несколько привязок или быть пустым. Сбой модели фиксируется отдельным статусом в трассе решения.
- Сравнить с действующей маршрутизацией на общем наборе размеченных новостей об акциях. Для других классов добавить примеры с ручной разметкой. Проверить пропущенные и лишние привязки, межотраслевые новости, задержку и стоимость.
