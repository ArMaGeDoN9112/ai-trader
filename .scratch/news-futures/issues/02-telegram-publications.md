# 02: Непрерывное получение публикаций из Telegram

**What to build:** Текстовые публикации MarketTwits и РБК поступают через общий MTProto-адаптер в архив и существующую контрольную обработку. Оператор видит публикации, их редакции и статус обработки; следующий канал того же типа добавляется настройкой.

**Blocked by:** 01 — Контрольная публикация проходит всю цепочку локально.

**Status:** resolved

- [x] При локальной пользовательской авторизации читаются только явно настроенные источники. Начальный список содержит MarketTwits и РБК; секреты и сессия не попадают в журнал или вход моделей.
- [x] При первом подключении сохраняются семь дней доступной истории как контекст; историческая загрузка не открывает позиции.
- [x] Новые публикации и доступные редакции сохраняются с идентификатором канала и сообщения, временем, ссылкой и исходным текстом. Предыдущие полученные редакции не теряются.
- [x] Обрабатывается только текст, включая полученную текстовую подпись. Содержание изображений, аудио и видео не считается прочитанным.
- [x] Повтор транспортной доставки не создаёт новую публикацию-редакцию или повторное задание обработки.
- [x] При сбое сохранения доставка не считается успешно обработанной; ошибки одного источника видны и не останавливают остальные источники.
- [x] Состояние доставки сохраняется с учётом MTProto-сессии и отдельных каналов. Недоступная история и невосстановимые промежуточные редакции обозначаются явно.
- [x] Добавление ещё одного Telegram-канала не требует изменения логики анализа. Контракт публикаций допускает будущий адаптер сайта без изменения торговой цепочки.
- [x] Проверки на контролируемом транспорте покрывают историю, новую публикацию, редакцию, повтор и ошибку сохранения; реальное получение двух начальных каналов подтверждается отдельно.

сессия вне репозитория. Зависимости закреплены в `requirements-telegram.txt`.
LangGraph и модельные зависимости здесь не нужны: обработка остаётся фиксированной
имитацией 01, а не рабочим агентным сценарием тикета 03.

| Критерий | Свидетельство |
| --- | --- |
| Настроенные источники и секреты | Валидация usernames, broadcast-каналов и принадлежности сообщений; скрытый локальный вход; отказ от сессии в репозитории; диагностика без текста исключений; тест изоляции session identity от обработки. |
| Семь дней контекста | `collect`: снимок `pts` перед историей; тест семидневного окна; `context_only`, без трассы исполнения. Граница секунды Telegram учитывается отдельно. |
| Публикации и редакции | Неизменяемые записи с ключом редакции; тест исходного текста, исправления и чтения после повторного открытия БД. |
| Текст и подписи | Нормализация `Message.message`; `unread_media`; тесты TL-типов с медиа и статуса `no_text`; скачивания медиа нет. |
| Повторы | Уникальный ключ редакции без времени повторного получения, username-ссылки и транспортной оболочки; тест повтора после обработки. |
| Сбои хранения и источников | SQLite-триггер ломает запись курсора после вставки редакции: вся транзакция откатывается; повтор начинается со старого `pts`; второй источник продолжает работу. |
| Восстановление | Привязка архива к аккаунту/локальной сессии; сохранён общий снимок `pts/qts/seq/date` и отдельные channel `pts`; явный pull от курсора приложения; тест перезапуска команды и очереди. |
| Недоступная история | Ошибка истории не завершает bootstrap; `TooLong` вызывает повторное сканирование от начала контекста и явное уведомление об утраченных промежуточных редакциях/удалённых постах. Полнота доступной истории не обещается. |
| Расширение | Третий username добавляется JSON-настройкой; общий контракт не содержит зависимости от Telegram SDK и пригоден будущему адаптеру сайта. |
| Контрольная цепочка | Новые текстовые редакции проходят три фиксированные роли 01 и независимую программную проверку; результат — только `simulation`, связан с исходной публикацией. История и сообщения старше 15 минут остаются контекстом. |

Проверки: `python -m unittest discover -s tests -v` — 28 тестов;
`python -m mypy --strict news_futures tests`; `python -m pip check`.
Результат: 28 тестов — OK; mypy — 11 файлов, ошибок нет; pip check — OK.
`git diff --check` — без ошибок форматирования.
На Windows для `asyncio` тесты требуют локального socketpair; запуск выполняется
вне сетевого ограничения песочницы, транспорт Telegram и брокер остаются подменёнными.
Офлайн-проверка 01 по-прежнему выполняется под собственным запретом I/O.

**Живая проверка 2026-11-08.** `telegram --once` через локальную MTProto-сессию
сохранил доступную историю за семь дней. MarketTwits — 963 записи, из них 960
с текстом. РБК — 423 записи, из них 371 с текстом. Все 1386 записей получили
`context_only` без трасс исполнения. Повторный запуск завершился с кодом 0,
сохранил курсоры обоих каналов и не добавил дубликатов. Новые публикации и
редакции во время двух запусков не поступили, эти ветки проверены на
контролируемом транспорте.
