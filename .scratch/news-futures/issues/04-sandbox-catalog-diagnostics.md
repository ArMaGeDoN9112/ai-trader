# 04: Проверяемое подключение к песочнице и каталогу инструментов

**What to build:** Оператор подключает песочницу Т-Инвестиций и получает диагностический результат: фактические MCP-возможности, состояние тестового счёта, каталог компаний и сведения о доступном фьючерсе на акцию. Диагностика подтверждает данные, необходимые для последующих торговых проверок, без отправки заявок.

**Blocked by:** 01 — Контрольная публикация проходит всю цепочку локально.

**Status:** ready-for-agent

- [ ] Подключение использует явно выбранный sandbox-контур и локальный токен; торговый контур реальных денег не подключается.
- [ ] Сохраняются фактические имена и схемы MCP-инструментов. Привязки операций проверяются по ним, а не угадываются по смыслу названий.
- [ ] Оператор видит состояние счёта, существующие позиции, обычные и защитные заявки с явно обозначенной доступностью каждого вида данных.
- [ ] Доступен каталог для привязки публикаций к компаниям; компания, акция и фьючерсный контракт не отождествляются.
- [ ] Для конкретного доступного фьючерса подтверждаются идентификаторы, базовая акция, лотность, валюта, шаг цены, стоимость шага, обеспечение, актуальность котировки и возможность торговли.
- [ ] Лоты заявки, число контрактов и единицы цены различаются; неподтверждённый пересчёт не считается готовым к торговле.
- [ ] Возможности полного Invest API не приравниваются к MCP. Отсутствие обязательного инструмента или поля даёт явное ограничение и не включает другой способ исполнения автоматически.
- [ ] Диагностика перечисляет доступные операции работы с SL/TP, их чтения и отмены; OCO, reduce-only и атомарный вход не объявляются поддержанными без доказательств.
- [ ] Проверки покрывают корректные ответы, отсутствие возможностей, неверные единицы, недоступный контракт и недопустимый контур. Контрольные результаты отличаются от подтверждённых ответов площадки.
- [ ] Токен и авторизационные данные не появляются в диагностическом выводе, архиве публикаций или запросах к моделям.
