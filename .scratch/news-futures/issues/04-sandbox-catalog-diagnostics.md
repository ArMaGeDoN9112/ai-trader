# 04: Проверяемое подключение к песочнице и каталогу инструментов

**What to build:** Оператор подключает песочницу Т-Инвестиций и получает диагностический результат: фактические MCP-возможности, состояние тестового счёта, каталог компаний и сведения о доступном фьючерсе на акцию. Диагностика подтверждает данные, необходимые для последующих торговых проверок, без отправки заявок.

**Blocked by:** 01 — Контрольная публикация проходит всю цепочку локально.

**Status:** resolved

- [x] Подключение использует явно выбранный sandbox-контур и локальный токен; торговый контур реальных денег не подключается.
- [x] Сохраняются фактические имена и схемы MCP-инструментов. Привязки операций проверяются по ним, а не угадываются по смыслу названий.
- [x] Оператор видит состояние счёта, существующие позиции, обычные и защитные заявки с явно обозначенной доступностью каждого вида данных.
- [x] Доступен каталог для привязки публикаций к компаниям; компания, акция и фьючерсный контракт не отождествляются.
- [x] Для конкретного доступного фьючерса подтверждаются идентификаторы, базовая акция, лотность, валюта, шаг цены, стоимость шага, обеспечение, актуальность котировки и возможность торговли.
- [x] Лоты заявки, число контрактов и единицы цены различаются; неподтверждённый пересчёт не считается готовым к торговле.
- [x] Возможности полного Invest API не приравниваются к MCP. Отсутствие обязательного инструмента или поля даёт явное ограничение и не включает другой способ исполнения автоматически.
- [x] Диагностика перечисляет доступные операции работы с SL/TP, их чтения и отмены; OCO, reduce-only и атомарный вход не объявляются поддержанными без доказательств.
- [x] Проверки покрывают корректные ответы, отсутствие возможностей, неверные единицы, недоступный контракт и недопустимый контур. Контрольные результаты отличаются от подтверждённых ответов площадки.
- [x] Токен и авторизационные данные не появляются в диагностическом выводе, архиве публикаций или запросах к моделям.

## Answer

Реализован только срез 04. Предусловие 01 проверено: все критерии отмечены,
контрольные тесты `test_local_scenario.py` повторно прошли (3 теста).

Команда `sandbox-diagnostics` использует официальный MCP SDK, точный sandbox URL
и токен из `.local/credentials.toml`. Первый запуск сохраняет `tools.json`,
повторный с проверенными привязками — чтения и `diagnostics.json`.
Схемы, свидетельства и аргументы проверяются до вызова. Никаких поручений,
автоматической подмены MCP полным API или подключения реального контура нет.
Каталог и спецификация связаны отдельными ID компании, акции и фьючерса.
Лотность кроме 1, неверные единицы, котировки из будущего и неполные сведения
не подтверждаются; `execution_enabled` всегда false.

Инструкция и живая приёмка: [docs/sandbox.md](../../../docs/sandbox.md).
Контрольные тесты используют вымышленные ответы, в том числе через HTTP
MockTransport настоящего MCP SDK. Контрольные артефакты помечены `control`;
ответы удалённого sandbox — `sandbox_mcp`. Транспортный тест подменяет HTTP
и не служит свидетельством подключения к площадке.

2026-11-08 получены 68 инструментов через `tools/list`. После проверки живой
схемы вызван `invest_list_broker_accounts` с `readOnlyHint: true` и фильтром
открытых счетов. При первом прогоне список был пуст. По запросу оператора один
виртуальный счёт создан через `invest_open_sandbox_account` и подтверждён чтением.
Повторная диагностика прочитала портфель на 0 ₽, пустые позиции, обычные и
защитные заявки. `execution_enabled: false`.

Получены 1910 записей акций и подтверждена связь актива Сбера, акции SBER и
фьючерса SRZ6. Спецификация SRZ6 сверена по UID, FIGI в проверенном ответе
отсутствует. Расчёт `invest_get_order_price` на один лот вернул обеспечение
3 634,2054 ₽ для покупки и 3 667,0536 ₽ для продажи. Площадка сообщила

при действовавшем тогда пороге 60 с. Итог `limited`: чтения подтверждены, нормализованный каталог
компаний и полный набор полей контракта пока не подтверждены. Локальные
артефакты: `.local/live-checks/sandbox-04-acceptance-ff592258c2/` и
`.local/live-checks/sandbox-04-contract-uid-c5d3585bea/`.

По запросу оператора верхний порог возраста котировки для диагностики 04 снят.
Возраст выводится при подтверждении контракта, отметки из будущего отклоняются.

Настройка `ca_file` позволяет штатной команде использовать проверенный локальный
корневой сертификат только в контексте подключения к sandbox MCP.

покупки и продажи одного лота, торговый статус и возраст котировки 300,54 с.
