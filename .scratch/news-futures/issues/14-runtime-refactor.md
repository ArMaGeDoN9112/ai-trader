# 14. Разделить обработку новостей и торговое исполнение

Status: resolved

Оператор запускает прежний профиль через CLI или локальную панель. Для
каждой редакции он видит причину пропуска, одобренное предложение либо
состояние торгового цикла, подтверждённое песочницей.

- Разделить конфигурацию, граф редакции, сверку счёта, запись результатов
  и исполнение заявок. Граф получает интерфейс чтения снимка и возвращает
  предложение приложению для независимой проверки.
- Сохранить идентификаторы и этапы контрольных точек, форматы трасс и записей
  журнала. Восстанавливать идентификаторы заявок и подтверждённые исполнения
  из одного журнала. При конфликте активных циклов блокировать запись брокеру.
- Проверить обычный вход, SL/TP, удержание и выход через команду `serve`
  с подменёнными интеграциями. Проверить повтор доставки, неопределённый ответ
  и конфликт циклов. Сохранить проверку тикета 01 без сторонних зависимостей.
- Ограничить интеграцию песочницей Т-Банка. Для двух независимых стопов
  действует существующее правило явного выбора в ручном контрольном сценарии.
