# 13: Установка и приёмка приложения

**What to build:** Оператор устанавливает приложение, настраивает подключения и запускает непрерывную работу по README. Протокол приёмки покрывает повседневную работу, расширение настроек, перезапуск и подтверждение брокерских операций в песочнице.

**Blocked by:** 12 — Перезапуск восстанавливает обработку и открытую позицию.

**Status:** needs-info

- [ ] Документированный запуск из чистого окружения Windows проверен. README ведёт от установки и настройки доступа к диагностике, непрерывной работе, просмотру решения и штатной остановке.
- [x] По примеру конфигурации можно изменить модель роли и добавить разрешённый Telegram-канал без правок кода. Новый тип источника подключается через описанный контракт публикации. Тест с дополнительным адаптером подтверждает, что остальная цепочка принимает его данные без специальных условий в графе.
- [x] Оператор может найти решение по идентификатору, понять причину отказа или статус исполнения и проверить позицию и защиту после перезапуска из того же каталога данных.
- [ ] Режим наблюдения проверен отдельно от прогона в песочнице с двумя начальными каналами, разрешёнными фьючерсами, выбранными моделями и отдельным sandbox-счётом.
- [ ] Подтверждены публикация, многозначная или косвенная привязка, событие и его обновление, контекст, предложение, критика, проверки риска, вход, SL/TP и полное закрытие.
- [x] Проверены повторная публикация, неоднозначное совпадение, исправление, отказ критика и один допустимый пересмотр без непроверенных вариантов.
- [x] Проверены устаревшее предложение, предел 500 ₽ планового риска, плечо 2×, единственная позиция, недопустимый минимальный объём и отсутствие дневного ограничения.
- [ ] Подтверждены перезапуск, восстановление старых публикаций для переоценки позиции, частичные исполнения, неопределённые ответы и аварийная процедура защиты.
- [ ] В результатах нет повторной или обратной позиции; оставшиеся защитные заявки и ограничения площадки учтены явно.
- [x] Отдельно представлены автоматические проверки с имитациями и фактические проверки Telegram, OpenRouter и MCP; отсутствующие доступы не отмечаются как успешно проверенные.
- [ ] Зафиксированы реальные задержки, доступные расходы, примеры качества на русских новостях, запрошенные и фактические модели и условия воспроизведения без секретов.
- [x] Неподтверждённая безопасная работа SL/TP или обязательная возможность MCP остаётся препятствием приёмке затронутой части.

## Результат прогона

[Протокол с результатами, замерами и открытыми проверками](../acceptance.md).
Отметки CLI, конфигурации и риска основаны на проверках с имитациями.
В чистом venv Windows установлены зависимости. Раздельно подтверждены чтение
двух Telegram-каналов и MCP, вызовы аналитика, критика и Jev через OpenRouter.
Сквозной живой `serve` заблокирован проверкой передачи данных в OpenRouter.
Автономные заявки в песочнице остаются заблокированы до подтверждения
безопасной совместной работы SL/TP и требуемой сверки операций.
