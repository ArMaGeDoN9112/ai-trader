# News-futures

Цель проекта — непрерывное приложение для анализа новостей и автономной
торговли фьючерсами с объяснимыми решениями, наблюдением без заявок и отдельным
режимом исполнения в песочнице. [Спецификация приложения](.scratch/news-futures/spec.md)
описывает рабочий процесс оператора, архитектуру и критерии готовности.

[Установка, непрерывный запуск и просмотр решений](docs/runtime.md).
Ниже описаны отдельные команды контроля и диагностики.

## Структура проекта

| Каталог | Ответственность |
| --- | --- |
| [application](news_futures/application/) | Запуск, обработка очереди и восстановление, профиль и отчёты |
| [agents](news_futures/agents/) | Jev, сопоставление событий, контекст компании, аналитик и критик |
| [news](news_futures/news/) | Публикации, редакции и SQLite-архив |
| [trading](news_futures/trading/) | Риск, сверка счёта, исполнение и журнал заявок |
| [adapters](news_futures/adapters/) | Подключения к Telegram, OpenRouter и песочнице Т-Банка |
| [operator](news_futures/operator/) | HTTP-панель, управление рабочим процессом и представление истории |
| [simulation](news_futures/simulation/) | Контрольный сценарий без сети и сторонних зависимостей |
| [common](news_futures/common/) | Файловые операции, пути конфигурации, локальные секреты и ошибки |

[cli.py](news_futures/cli.py) связывает команды с соответствующими модулями.
[Тесты](tests/) сгруппированы по тем же подсистемам, общие имитации и тестовые
данные находятся в [tests/support](tests/support/).

## Локальная панель оператора

Установите зависимости, авторизуйте Telegram и подготовьте
`.local/runtime.json` по [инструкции запуска](docs/runtime.md).
Из корня проекта выполните:

```powershell
.venv\Scripts\python -m news_futures operator-ui .local/runtime.json
```

Откройте [http://127.0.0.1:8765/](http://127.0.0.1:8765/). Если порт занят,
укажите `--port 8766` и откройте адрес из вывода команды.
Проверьте режим, счёт и контракты, нажмите **Запустить** и дождитесь статуса
«Работает». Для штатной остановки нажмите **Остановить** и дождитесь статуса
«Остановлен». **Перезапустить** останавливает текущий процесс и запускает новый
с тем же каталогом данных. После сбоя обработчик запускается по команде оператора.

Закрытие вкладки оставляет обработчик запущенным. Ctrl+C в терминале закрывает
панель и штатно останавливает обработчик. Остановка сохраняет очередь и
выставленную на платформе защиту. Чтобы выбрать другой профиль или применить
изменения общей конфигурации и списка источников, перезапустите панель.

Панель показывает текущую позицию и защиту после подтверждения в этом запуске.
При потере сверки, остановке или через 45 секунд без свежего подтверждения
текущее состояние становится неизвестным. Предыдущее подтверждение остаётся
видимым отдельно. Журнал команд сохраняется в `operator-commands.jsonl`
в каталоге `data_dir`.

Диагностика песочницы и каталога (срез 04): [инструкция](docs/sandbox.md).
Команда `python -m news_futures sandbox-diagnostics` только читает MCP;
первое подключение сохраняет схемы для проверки привязок оператором.

## Автономный контрольный сценарий — news-futures/01

Сценарий `run` на Python использует фиксированные источник, компанию, акцию,
фьючерс, ответы маршрутизатора, аналитика и критика, цену исполнения и часы.
Контрольные данные находятся в `news_futures/simulation/control.json`. Ссылка на
`example.invalid` служит идентификатором оригинала и не открывается.

## Запуск из чистого окружения

Нужен только Python 3.11 или новее. Сторонних библиотек, ключей и сетевого
подключения для сценария и тестов не требуется. Выполняйте команды из корня
репозитория:

```console
python -m news_futures run .local/control-01
python -m news_futures show .local/control-01
```

В Windows можно заменить `python` на `py -3.11`, если интерпретатор установлен
через Python Launcher. Если команда указывает на неработающий псевдоним Microsoft
Store, используйте путь к установленному `python.exe`.

Первая команда возвращает JSON с `mode: "simulation"`,
`status: "simulated_filled"` и абсолютными путями к результатам. Вторая команда
читает трассу с диска после завершения первого процесса. Контрольный результат:
один условный контракт `control-future-2026-12`, long, цена 300.

Каталог запуска должен быть новым: существующий каталог не перезаписывается.
Чтобы получить новый каталог автоматически, выполните `python -m news_futures run`
и используйте путь `directory` из ответа для `show`.

## Что сохраняется

- `publication.json`: исходный текст, источник, внешний и составной устойчивый
  идентификаторы, ссылка, время публикации и получения. Записывается до ролей.
- `trace.json`: публикация, каталог с отдельными компанией, акцией и фьючерсом
  с экспирацией; последовательность ролей с входами и фиксированными ответами;
  программная проверка и результат исполнения с причиной входа и ссылками на
  предложение, компанию, контракт и публикацию.

Время `clock` и обе временные отметки публикации относятся к фиксированным часам
имитации, а не к фактическому времени запуска. Поэтому повторение в новом каталоге
даёт одинаковую трассу. Все роли и исполнение помечены `simulation`.

Исполнитель сам вызывает независимую проверку: проверяет связи публикации и
каталога, разрешённый контрольный контракт, согласие критика на идентификатор
предложения, одну условную единицу, сторону long, положительные целые цены,
порядок SL < вход < TP и непустую причину входа. При отказе результат — `rejected`,
без условного исполнения. Ответ критика не может отключить программную проверку.

Это проверка контрольного примера. Расчёт объёма и денежного риска, сроки
актуальности, сверка счёта и нативная защита относятся к следующим задачам.
В команде `run` нет транспорта, клиентов API, загрузки секретов и отправки поручений.
Если процесс прерван, исходная публикация остаётся; незавершённый запуск
не считается успешным без `trace.json`. Для повторения используйте новый каталог.

## Проверки

```console
python -m unittest discover -s tests -v
```

Сквозной тест запускает команду в отдельном изолированном Python-процессе (`-I -S`,
без сторонних site-packages),
убирает переменные с ключами и через audit hook запрещает создание сокетов,
сетевые операции и запуск внешних программ. Отдельные пробы подтверждают,
что запрет работает для сокета, HTTP, подпроцесса и shell. Затем другой процесс
читает и проверяет сохранённую трассу. Также проверяются воспроизводимость,
защита от перезаписи и отказы независимого исполнителя.

Для разработки и проверки типов (только этот шаг загружает инструмент из PyPI):

```console
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements-dev.txt
.venv\Scripts\python -m mypy --strict news_futures tests
```

На Linux/macOS используйте `.venv/bin/python`. Каталог `.local`, виртуальное
окружение и кэши исключены из Git. Последующие срезы описаны ниже;
контрольный сценарий остаётся независимым от их зависимостей.

## Telegram — news-futures/02

Получение реальное, последующая обработка — **имитация из 01** с фиксированными
ответами трёх ролей. Привязка к контрольной компании и условное исполнение
не являются результатом анализа новости. Модели и брокер не подключаются.
Для `run`/`show` по-прежнему достаточно стандартной библиотеки.

Установите зависимости отдельно:

```console
.venv\Scripts\python -m pip install -r requirements-telegram.txt
```

Нужны собственные `api_id` и `api_hash` из [Telegram API Development](https://my.telegram.org).
В Telegram этого пользовательского аккаунта заранее подпишитесь на
[@markettwits](https://t.me/markettwits) и [@rbc_news](https://t.me/rbc_news).
Коллектор не вступает в каналы автоматически и не читает сообщения других чатов.

Заполните `api_id` и `api_hash` в секции `[telegram]` файла
`.local/credentials.toml` и запустите локальную авторизацию:

```powershell
.venv\Scripts\python -m news_futures telegram-login
```

Телефон, код и пароль 2FA вводятся скрыто в локальном интерактивном терминале.
Не передавайте их в чат. Сессия по умолчанию находится в
`%LOCALAPPDATA%\news-futures\telegram\user.session` (Linux/macOS:
`$XDG_STATE_HOME/news-futures/telegram` или `~/.local/state/news-futures/telegram`).
Рядом создаётся `user.identity` — постоянная идентичность локальной сессии.
Храните эти файлы вместе; не копируйте их в репозиторий или журнал.
Для другого пути обе команды поддерживают `--session <путь вне репозитория>`.
Архив проверяет совпадение идентичности сессии и аккаунта; для другой сессии
нужен отдельный архив (`--database <путь>`).

```console
.venv\Scripts\python -m news_futures telegram --once
.venv\Scripts\python -m news_futures publications
.venv\Scripts\python -m news_futures telegram
```

`--once` загружает историю и догоняет доступные изменения обоих источников,
обрабатывает очередь и завершает процесс; ненулевой код означает ошибку хотя бы
одного источника. Без этого флага получение работает непрерывно до Ctrl+C.
Каждый канал имеет независимый цикл и ожидание FloodWait: ошибка одного
источника не останавливает остальные. Запускайте один коллектор на сессию.

Начальный список — `news_futures/adapters/telegram-sources.json`. Новый канал добавляется
в массив `channels` без `@`, изменения кода анализа не требуются. Свой JSON-файл
можно передать через `--config`. У аккаунта должна быть подписка на этот канал.

Архив по умолчанию: `.local/telegram/archive.sqlite3`. Команда `publications`
показывает исходные тексты, ссылки, стабильные `(channel_id, message_id)`,
время публикации/получения/редакции, все полученные редакции, состояния каналов,
уведомления о пробелах и трассы контрольной обработки. Статусы редакций:

| Статус | Значение |
| --- | --- |
| `context_only` | Первоначальная история либо публикация старше 15 минут; исполнения нет. |
| `no_text` | Нет текста/подписи либо получено удаление; исполнения нет. |
| `pending` | Архив и задание сохранены; ожидается контрольная обработка. |
| `simulated` | Сохранена трасса имитации трёх ролей и программной проверки. |

Первое подключение каждого канала сохраняет семь дней **доступной** истории
только как контекст. Читаются текст и подписи; медиа не загружаются и не
анализируются, наличие непрочитанного содержимого отмечается `unread_media`.
Редакция определяется содержимым и временем редактирования, а не временем доставки.
Изменение текста и возврат к прежнему тексту с новым временем редакции сохраняются
отдельно. Повтор доставки не сбрасывает статус и не создаёт новое задание.

Редакции, задания и `pts` канала фиксируются одной SQLite-транзакцией.
При ошибке сохранения курсор остаётся прежним: следующий запрос повторяет доставку.
Очередь обрабатывается независимо от приёма; незавершённые задания остаются на диске.
До обработки повторно проверяется возраст публикации.

Сессия обслуживается Telethon, состояние приложения восстанавливается явным
[`updates.getChannelDifference`](https://core.telegram.org/method/updates.getChannelDifference)
от сохранённого `pts` каждого настроенного канала. Снимок общего `pts/qts/seq/date`
и локальная идентичность сессии хранятся отдельно от публикаций. Общая очередь
личных чатов не служит источником публикаций; фоновые подтверждения SDK не
продвигают курсоры приложения. Аккаунт, сессия и ключи не передаются в обработку.

При [`channelDifferenceTooLong`](https://core.telegram.org/constructor/updates.channelDifferenceTooLong)
доступная история повторно сканируется от начала первоначального окна, включая
старые посты с возможными исправлениями. Курсор продвигается после сохранения.
Сканирование истории не восстанавливает полный журнал редакций: удалённые
публикации и утраченные промежуточные редакции явно отмечаются в `notices`.
Даже успешная первоначальная загрузка не доказывает полноту истории Telegram;
это также отражено в уведомлениях. Отказ API истории даёт ошибку и не завершает
первоначальную загрузку успешно.

Ошибки выводят только источник и класс исключения, без текста RPC-запроса или
исключения. Для ошибок данных доступа проверьте секцию `[telegram]` в `.local/credentials.toml`.
`ModuleNotFoundError`: установите зависимости; `ValueError`: проверьте JSON,
авторизацию, подписку, путь сессии и соответствие архива аккаунту.
Коды `FloodWaitError`, `ChannelPrivateError` и подобные видны в stderr и `notices`.

### Проверка приёмки 02

```console
.venv\Scripts\python -m unittest discover -s tests -v
.venv\Scripts\python -m mypy --strict news_futures tests
```

Контролируемый транспорт проверяет историю, новые публикации, редакции, повтор,
сбой сохранения и повторную доставку, восстановление очереди, неполноту истории,
изоляцию ошибок источников и отсутствие секретов в диагностике. Тесты адаптера
используют настоящие TL-типы установленного Telethon без Telegram-соединения.
Без зависимостей Telegram эти SDK-тесты пропускаются; тесты 01 остаются офлайн.
На Windows `asyncio` требует разрешённый локальный socketpair даже для тестов
с контролируемым транспортом.

**Живая проверка 2026-11-08** подтвердила получение истории MarketTwits и РБК
через MTProto. Все 1386 записей сохранились со статусом `context_only`.
Повторный `telegram --once` с тем же архивом завершился без дублей.
Новые публикации и редакции проверены на контролируемом транспорте.

## OpenRouter — news-futures/03

Отдельная команда `analyze` запускает аналитика и критика с ограниченным
пересмотром. Настройка, контекст, журнал и состояние приёмки:
[инструкция OpenRouter](docs/openrouter.md). Торговые поручения не отправляются.
