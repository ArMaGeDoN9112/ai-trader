# Приёмка защищённого цикла в песочнице

## Контрольный брокер

```powershell
.venv\Scripts\python -m unittest discover -s tests -p test_sandbox_execution.py -v
.venv\Scripts\python -m unittest discover -s tests -p test_tbank_execution.py -v
```

`SandboxExecutor.start` принимает архив публикаций, сохранённое согласие
критика и разрешённые контракты. Проверки 08 читают свежий снимок брокера и
в одной транзакции сохраняют резерв и запись цикла. Намерение с устойчивым ID
сохраняется до каждого торгового вызова. После прерывания `reconcile` читает
площадку с ID сохранённых операций. Неопределённость оставляет резерв занятым.
Для short лимит плеча рассчитывается с запасом до уровня SL. Если цена
исполнения вышла за пределы защитного диапазона, исполнитель запускает
аварийную сверку и закрытие.

Для подтверждения защиты нужны оба активных поручения, верные сторона и
уровни в пунктах, объём оставшейся позиции в лотах. Исполнитель размещает
SL первым, сверяет его и только после этого размещает TP. У каждой заявки
свой устойчивый ключ. Контрольный выход
`reconcile(close=True)` сначала снимает защиту и сверяет её дочерние заявки,
затем закрывает фактический остаток. При подтверждённом отсутствии защиты
исполнитель выполняет ту же процедуру без модели. Полное закрытие требует
сверенных исполнений, нулевой позиции и отсутствия активных заявок.
Если после попытки закрытия подтверждён ненулевой остаток, цикл остаётся
заблокированным. При `close_residual_pending` следующий `reconcile` заново
сверяет все предыдущие операции и может отправить отдельный выход только
на подтверждённый остаток. За одну сверку отправляется максимум один запрос
на закрытие. Если последнее закрытие не уменьшило позицию, цикл остаётся
заблокированным с причиной `exit_or_cancellation_unconfirmed`.

### Обработка сбоев в тикете 10

При недоступности брокера журнал сохраняет `broker_read_unavailable`, а
резерв счёта остаётся занятым. При восстановлении обычная заявка ищется по
устойчивому ключу запроса. Исполнитель отменяет незавершённый остаток входа
или дочернего выхода, только если ID этого поручения подтверждён сверкой и
присутствует в списке активных заявок. До завершения остатка входа защитные
заявки не выставляются. Объём обоих стопов берётся из итогового исполнения.
Отправленному рыночному выходу исполнитель даёт завершиться и до этого
сохраняет блокировку нового входа.

Для новостного намерения предусмотрен `reconcile(close=True, cycle_id=...)`.
ID относится к позиции, которую оценивали аналитик и критик. Сверка отклоняет
такое намерение, если на счёте уже другая позиция. Само подключение новостного
потока к исполнителю относится к тикету 11. Любой программный выход ждёт
подтверждения отмены или исполнения стопов и завершения дочерних заявок.
Если сработали оба стопа и появилась обратная позиция, результат
`fills_and_position_disagree` блокирует следующий вход.

Журнал доступен из базы событий. Поле `source` различает контролируемого
брокера и песочницу площадки.

```powershell
.venv\Scripts\python -m news_futures sandbox-trades --database .local/events.sqlite3
```

## Контрольная сделка в песочнице Т‑Инвестиций

Исполнитель 09 обращается к официальному Sandbox REST API. REST принимает
ключ операции для входа и стопов и позволяет искать обычную заявку по ключу.
В проверенной схеме MCP этих полей нет. Счёт должен быть отдельным
sandbox-счётом с тестовым капиталом. Для входа нужны свежая котировка,
действующая торговая сессия и сохранённое согласие критика в режиме `sandbox`.
Для SRZ6 подтверждена лотность 1 и численное равенство цены в пунктах и рублях.

```powershell
.venv\Scripts\python -m news_futures sandbox-trade start --allow-independent-stops --account $accountId --contract $contractUid --company $companyId --approval $approvalDirectory --ca-file $sandboxCA
.venv\Scripts\python -m news_futures sandbox-trade reconcile --account $accountId --contract $contractUid --ca-file $sandboxCA
.venv\Scripts\python -m news_futures sandbox-trade close --account $accountId --contract $contractUid --ca-file $sandboxCA
```

ID счёта, контракта и компании берутся из диагностики 04 и каталога. При
необходимости укажите `--database` для базы событий и `--publications` для
архива публикаций. `--ca-file` нужен при использовании локального доверенного
сертификата. Для выделенного sandbox-счёта все запуски используют одну базу
событий. В ней хранится резерв, а блокировка сериализует параллельные команды.
Стопы нативно срабатывают на стороне площадки. Для снятия второго
стопа после активации первого запустите `reconcile`. Если два исполнения
открыли обратную позицию, сверка заблокирует новый вход и покажет расхождение
в журнале. Повторная отмена разрешается после чтения статуса только для
стопов, которые площадка всё ещё показывает активными. Если ответ на
постановку стопа потерян, сверка возвращает `protection_submission_unconfirmed`.
Список стопов не содержит ключа запроса. Оператору потребуется проверить
позиции и стопы вручную. История обычных заявок в песочнице хранится семь дней.

Флаг `--allow-independent-stops` предназначен для контрольного запуска
оператором. Для автономного входа с двумя стопами требуется подтверждённая
брокером защита от двойного исполнения. Текущие REST и MCP схемы такой
гарантии не дают. Автономный сценарий с независимыми SL/TP остаётся выключен.
[Чтение состояния обычной заявки](https://developer.tbank.ru/invest/api/sandbox-service-get-sandbox-order-state) ·
