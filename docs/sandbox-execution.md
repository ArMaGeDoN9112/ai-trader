# Приёмка защищённого цикла в песочнице

## Контрольный брокер

```powershell
.venv\Scripts\python -m unittest discover -s tests -p test_sandbox_execution.py -v
```

`SandboxExecutor.start` принимает архив публикаций, сохранённое согласие
критика и разрешённые контракты. Проверки 08 читают свежий снимок брокера и
в одной транзакции сохраняют резерв и запись цикла. Намерение с устойчивым ID
сохраняется до каждого торгового вызова. После прерывания `reconcile` читает
площадку с ID сохранённых операций. Неопределённость оставляет резерв занятым.
Для short лимит плеча рассчитывается с запасом до уровня SL. Если цена
исполнения вышла за пределы защитного диапазона, исполнитель запускает
аварийную сверку и закрытие.

Для подтверждения защиты нужны оба активных поручения, верные сторона и
уровни в пунктах, объём оставшейся позиции в лотах. Контрольный выход
`reconcile(close=True)` сначала снимает защиту и сверяет её дочерние заявки,
затем закрывает фактический остаток. При подтверждённом отсутствии защиты
исполнитель выполняет ту же процедуру без модели. Полное закрытие требует
сверенных исполнений, нулевой позиции и отсутствия активных заявок.
Если после попытки закрытия подтверждён ненулевой остаток, цикл остаётся
заблокированным с причиной `exit_or_cancellation_unconfirmed`.

Журнал доступен из базы событий. Поле `source` различает контролируемого
брокера и песочницу площадки.

```powershell
.venv\Scripts\python -m news_futures sandbox-trades --database .local/events.sqlite3
```

## Фактический прогон Т‑Инвестиций, 8 ноября 2026

Повторное получение актуальной схемы MCP с настройками из репозитория.

```powershell
.venv\Scripts\python -m news_futures sandbox-diagnostics .local/live-checks/sandbox-09-inventory
```

Для чтения состояния счёта и контракта в прогоне использовался локальный
профиль SRZ6 из доработки диагностики 04. Команда с этим профилем приведена ниже.

```powershell
.venv\Scripts\python -m news_futures sandbox-diagnostics .local/live-checks/sandbox-09-recheck --config .local/sandbox-settings.json
```

Получено в 23:51 МСК через sandbox MCP. Сохранённые ответы находятся в
`.local/live-checks/sandbox-09-preflight-4afd1327a6/`, в файлах
`tools.json` и `diagnostics.json`.

| Проверка | Ответ площадки |
| --- | --- |
| Счёт | Один открытый sandbox-счёт, 0 ₽, нет позиций, обычных и защитных заявок |
| SRZ6_SPBFUT | Котировка 29 868 пунктов, 8 ноября 2026 в 18:59 МСК. Доступность лимитной и рыночной заявок — false, статус `BREAK_IN_TRADING` |
| Схемы | 68 инструментов. Вход и отдельные SL/TP принимают пункты и лоты. Выставление SL/TP возвращает ID. Чтение стопов показывает статус и ID дочерней заявки |
| Восстановление по ID | `invest_create_order` и `invest_create_stoporder` не принимают ключ запроса клиента. Чтение состояния обычной заявки требует биржевой ID |
| Взаимодействие SL/TP | Схемы не подтверждают исключение превышения остатка позиции, нативное связывание двух стопов или атомарный вход |

Код выхода диагностики 1, статус `limited`, причина
`contract_unavailable`. Торговая часть приёмки заблокирована. Для подключения
записи нужен подтверждённый механизм, который позволяет SL и TP работать
одновременно и не открыть обратную позицию при отключённом клиенте.
Независимые стопы из текущих схем такого подтверждения не дают. Приёмка
с исполнением, проверкой нативного срабатывания после отключения клиента и
финальной сверкой остаётся открытой. Заявки в этом прогоне не отправлялись.
