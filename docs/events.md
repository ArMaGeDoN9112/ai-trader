# Повторы и обновления событий

Для каждой текстовой редакции экспортируйте полный объект `publication` из
команды `publications` и обработайте его командой [`route`](jev.md). Передайте
каталог завершённого запуска `route` в `event-match`. Используйте один и тот же
файл SQLite для последовательных редакций. По умолчанию это
`.local/events.sqlite3`.

```powershell
.venv\Scripts\python -m news_futures event-match .local/route-06-first
.venv\Scripts\python -m news_futures event-match .local/route-06-next
.venv\Scripts\python -m news_futures events --company COMPANY_ID
```

Поиск ранжирует прежние события по общей редакционной истории, совпадению
начала слов и привязкам компаний. Модель получает до восьми кандидатов
с первым и двумя последними существенными материалами и, если есть,
предыдущей редакцией той же публикации. Если остались только повторы,
используются доступные материалы. В `search` видны объём поиска и
идентификаторы материалов, переданных модели. `unmatched` означает, что
совпадение среди этих кандидатов не установлено. Поиск может пропустить
событие, например при перефразировании без общих слов или привязок.

Модель сопоставляет конкретное событие и отдельно оценивает изменение
сведений. Для независимого подтверждения нужна цитата из поступившего
материала с указанием самостоятельного получения сведений. Программа
проверяет, что цитата есть в тексте, содержит явный признак самостоятельной
проверки и не повторяет цитату кандидата. Для известных русских и английских
формулировок эта проверка отличает, например, «по собственным замерам» от
«по данным РБК». Нераспознанное подтверждение остаётся спорным обновлением
и передаётся на анализ. Оператор может сверить цитату, объяснение и первичные
публикации. Удаление сообщения без текста само по себе не свидетельствует об
опровержении.

В `events` текущие материалы находятся в `context`, а все решения с
исходниками и привязками находятся в `history`. Повтор сохраняется в
контексте без задания, с исходной датой основания события `basis_at`.
Дата самой поступившей редакции доступна в `publication`. При сомнении
в совпадении создаётся отдельная запись с возможной связью в `assessment`.
В контексте видны обе стороны спорной связи. Если привязки Jev отсутствуют
и модель не выделила единственного кандидата, запросы на проверку получают
компании из подобранного списка.
При ошибке модели решение `model_error` сохраняется с диагностикой,
а команда возвращает код 1. Неопределённость и ошибки модели сохраняют
возможность анализа. Повтор той же редакции возвращает сохранённое решение.

Для каждой компании из `analysis_company_ids` текущего решения сохранён запрос на
анализ. Его устойчивый ключ состоит из `decision_id` и ID компании. Для
обновлений включаются компании события и новой редакции, даже если у самой
редакции отсутствуют привязки Jev. Обработчик контекста и запросов относится
к тикету 07. `basis_at` сохраняет основание, известное в момент решения.
`event_bases` показывает текущие основания после исправлений. Если в событии
остались только перепечатки, текущее основание отсутствует. Для оценки
свежести новой информации доступна собственная дата её публикации.

Модель выбирается в `event-model.json` или через `event-match --config`.
При наличии кандидатов команда делает один тарифицируемый структурированный
запрос OpenRouter. Используются [зависимости и ключ OpenRouter](openrouter.md).
В `call` сохраняются настройки, фактическая модель, доступные сведения
о провайдере, расходах и ответе.

## Исправление решения

Возьмите `revision` исправляемой редакции и `event_id` события назначения из
`events`. `repeat` присоединяет редакцию без нового задания. `update`
присоединяет её и записывает запросы на пересмотр затронутых контекстов.
`separate` отделяет редакцию в собственное событие и записывает запросы
на пересмотр. При `separate` опустите `--event`.

```powershell
.venv\Scripts\python -m news_futures event-correct REVISION --kind update --event EVENT_ID --reason 'Первичный источник исправил цифру'
```

Исправление действует на указанную редакцию. Предыдущие решения остаются
в `history` с `current: false`. История показывает причину исправления и
номер заменённого решения. Оператор может отдельно исправить любую связанную
редакцию.

## Проверка приёмки

```powershell
.venv\Scripts\python -m unittest discover -s tests -p test_events.py -v
.venv\Scripts\python -m mypy --strict news_futures tests
```

Тесты используют штатные команды CLI и контролируемый HTTP-транспорт
OpenRouter. Проверяются повторная доставка, перепечатка, разные события на
одну тему, новые факты, исправление числа, опровержение, независимое
подтверждение, спорная связь, ограничение поиска и история исправлений.
