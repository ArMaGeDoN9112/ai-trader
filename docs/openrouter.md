# Аналитик и критик — news-futures/03

Предусловие 01 выполнено и повторно проверено изолированными тестами `-I -S`.
Команды `run` и `show` по-прежнему используют только стандартную библиотеку.
`analyze` — отдельный LangGraph-цикл с реальными LLM через OpenRouter.
Telegram, маршрутизатор и брокер к этому циклу не подключаются: по умолчанию
публикация, привязка, рынок и счёт — контрольные данные из 01.

## Запуск

Python 3.11+, из корня репозитория:

```console
.venv\Scripts\python -m pip install -r requirements-openrouter.txt
```

В локальном PowerShell 7 прочитайте ключ без сохранения значения в истории:

```powershell
$env:OPENROUTER_API_KEY = Read-Host 'OpenRouter API key' -MaskInput
.venv\Scripts\python -m news_futures analyze .local/openrouter-03
.venv\Scripts\python -m news_futures show .local/openrouter-03
```

Вызовы платные согласно тарифам выбранных моделей. Каталог запуска должен быть
новым; без пути он создаётся автоматически. Ключ остаётся в окружении локального
процесса, не включается в настройки, сообщения или журнал. Не передавайте ключ
в чат. LangSmith-трассировка для этого сценария отключена.

`--config <JSON>` задаёт отдельные `analyst` и `critic`. Пример по умолчанию —
`news_futures/openrouter-models.json`. У каждой роли свои `model`, `max_tokens`,
`timeout_ms` и необязательная `temperature` (0–2). Ненужные параметры и ключи
отклоняются. Начальный ID `openai/gpt-4.1-mini` — пример конфигурации, живое
подключение в окружении разработки не подтверждено. Используйте точный ID,
возвращаемый OpenRouter, и модель с поддержкой обязательного JSON Schema.

Настройки читаются один раз в начале цикла. SHA-256 нормализованного снимка —
версия настроек. Обе роли и единственный возможный пересмотр используют этот
снимок. Правка файла действует со следующего запуска. Параметры схемы,
`provider.require_parameters=true`, endpoint и отсутствие инструментов
зафиксированы кодом; конфигурация модели их не отменяет.

## Заданный контекст

Сохраните контрольный контекст и при необходимости измените его локально:

```console
.venv\Scripts\python -c "import json; from pathlib import Path; from news_futures.analysis import control_context; Path('.local/context-03.json').write_text(json.dumps(control_context(), ensure_ascii=False, indent=2), encoding='utf-8')"
.venv\Scripts\python -m news_futures analyze --context .local/context-03.json
```

Поля контекста: `publication`, `catalog`, `company_link`, `market`, `account`,
`position`, `entry_reason`. Компания, акция и фьючерс должны быть связаны,
а привязка — ссылаться на исходную публикацию и компанию. Сценарий 03 принимает
один заранее заданный инструмент; поиск и выбор из каталога относятся к следующим
тикетам. `market` и `account` содержат предоставленные оператором данные, их
актуальность этот срез не подтверждает. Не включайте в них credentials или сессии.

При открытой позиции `position` имеет вид
`{"contract_id":"control-future-2026-12","side":"long","quantity":1}`,
а `entry_reason` содержит сохранённую причину входа. Допустимы только `hold`
и полное новостное `close` этого контракта. Без позиции — `enter` (long/short)
либо `skip`. Объём входа модель не назначает; денежный риск и объём — тикет 08.

Текст публикации и ответы других моделей находятся в сообщениях с данными;
инструкции роли — в системном сообщении. Модели не получают инструментов или
доступа к настройкам/исполнителю. Код независимо проверяет ссылки, действия,
стороны и порядок положительных конечных цен; лишние поля отклоняются.
Эти меры не доказывают достоверность новости или правильность вывода модели.

## Результат и журнал

Сначала сохраняются `publication.json`, `context.json`, `settings.json`.
После каждого запроса — `call-01.json` и далее: вход, исходный ответ,
валидированный результат, запрошенная/фактическая модели, доступный провайдер,
версия настроек, задержка, tokens/cost и доступные метаданные. Ошибки сохраняют
класс исключения без его потенциально секретного текста. Отсутствующие сведения
обозначаются `null`, расход не оценивается по догадке. Итог — `trace.json`.

После возражения возможны один изменённый вариант и одна повторная критика;
критик повторно получает исходный контекст и прежние возражения. Программный ID
связывает согласие с точным вариантом. Повторный отказ, неизменённый пересмотр,
неверный ID, противоречивое согласие, невалидный JSON, отказ модели, обрыв,
неподдерживаемая схема и сетевая ошибка завершают цикл без допуска.

| Статус | Значение |
| --- | --- |
| `approved_for_checks` | Обе роли согласовали `enter` или `close`; `approved_proposal` содержит только проверенный вариант. |
| `no_action` | Согласован `skip` или `hold`; `approved_proposal` равен `null`. |
| `rejected` | Согласия/валидного ответа нет; `approved_proposal` равен `null`; код завершения CLI — 1. |

`approved_for_checks` **не разрешает торговлю**. Живого исполнителя нет;
`execution.status` всегда `not_requested`. Расчёты риска, проверка возраста,
сверка счёта, брокер и защита относятся к следующим тикетам. После прерывания
неполный каталог без итоговой трассы не считается согласованным циклом;
восстановление графа из checkpoint в 03 не реализуется.

## Приёмка

```console
.venv\Scripts\python -m unittest discover -s tests -p test_openrouter.py -v
.venv\Scripts\python -m unittest discover -s tests -v
.venv\Scripts\python -m mypy --strict news_futures tests
```

Контролируемый HTTP endpoint проверяет реальные LangChain/SDK-вызовы без платной
сети. Отдельный тест документирует потерю provider в ChatOpenRouter; причина
фиксированной совместимой интеграции описана в
[OpenRouter integration evidence](agents/openrouter-compatibility.md).

Живой пункт приёмки остаётся открытым: в окружении реализации отсутствует
`OPENROUTER_API_KEY`. После локальной настройки выполните `analyze` в новом
каталоге. У обеих ролей должны сохраниться фактические модели, валидированные
ответы и метаданные без транспортных/схемных ошибок. Если критик возражает,
допустим `rejected`: технический доступ не требует одобрения сделки.
Успешная проверка подключения не является проверкой качества стратегии.
