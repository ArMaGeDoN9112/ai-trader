# Domain docs

This repo uses a single-context layout:
`GLOSSARY.md` at the root and ADRs in `docs/adr/`.

## Before exploring

Read `GLOSSARY.md` and ADRs relevant to the area being explored.

If these files do not exist, proceed silently. Domain-modeling creates
them lazily when terms or decisions are resolved.

## Vocabulary

Use domain terms as defined in `GLOSSARY.md` in issue titles,
proposals, hypotheses, and tests.

If a term is missing, reconsider whether it belongs to the project
or note the gap for domain-modeling.

## ADR conflicts

Explicitly identify any existing ADR your proposal contradicts
and explain why the decision should be reopened.
