# Диагностика песочницы — news-futures/04

Команда только читает MCP. Она не создаёт и не пополняет счёт, не отправляет,
не отменяет заявки и не подключает модели. Счёт песочницы должен уже существовать.
Задачи 05–13 и допуск к торговле в этот срез не входят.

## Подключение

Нужен Python 3.11+ и отдельные зависимости:

```console
.venv\Scripts\python -m pip install -r requirements-sandbox.txt
```

Совместимые версии закреплены в `requirements-sandbox.lock` (Windows, Python 3.11).
Контрольный сценарий 01 по-прежнему работает со стандартной библиотекой.
Адрес песочницы взят из [официальной документации T-Invest MCP](https://developer.tbank.ru/invest/mcp).
Клиент использует [официальный MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk/tree/v1.28.0).
HTTP-редиректы, другие адреса и прокси из окружения запрещены. Транспорт проверяет
адрес каждого запроса. Общий таймаут подключения и диагностики — 120 секунд.

В локальном PowerShell 7 введите собственный токен, не передавая его в чат:

```powershell
$env:TINVEST_SANDBOX_TOKEN = Read-Host 'Токен для песочницы' -MaskInput
.venv\Scripts\python -m news_futures sandbox-diagnostics
Remove-Item Env:TINVEST_SANDBOX_TOKEN
```

Рекомендуется токен только для чтения. Авторизация передаётся в HTTP-заголовке
`Authorization: Bearer …`, в настройках токена нет. Настройки по умолчанию —
`news_futures/sandbox-settings.json`: обязательные `environment: "sandbox"`,
точный `endpoint` и пустые `bindings`. Другой контур отвергается до создания клиента.
Для другого файла: `--config .local/sandbox-settings.json`.

Первый запуск сохраняет фактические схемы в новом каталоге
`.local/news-futures-04/<uuid>/tools.json`. Он не угадывает имена операций и поэтому
возвращает `status: "limited"` и код 1. `diagnostics.json` и stdout содержат
доступность каждой операции и причины ограничений. Можно указать новый каталог
позиционным аргументом; существующий не перезаписывается. Ошибка подключения
не считается пустым списком позиций или успешной диагностикой.

## Проверенные привязки

Откройте локальный `tools.json`, проверьте назначение инструментов по описанию и
схемам и скопируйте настройки в `.local/sandbox-settings.json`. Для каждой операции
задайте привязку ниже. Это **контрольный пример формата**, имена и схема не
являются подтверждёнными инструментами Т-Банка:

```json
{
  "environment": "sandbox",
  "endpoint": "https://sandbox-invest-public-api.tbank.ru/mcp",
  "bindings": {
    "positions": {
      "tool": "CONTROL_read_positions",
      "input_schema": {
        "type": "object",
        "properties": {"accountId": {"type": "string"}},
        "required": ["accountId"],
        "additionalProperties": false
      },
      "arguments": {"accountId": "CONTROL_SANDBOX_ACCOUNT"},
      "result_path": "/positions",
      "evidence": {"/description": "CONTROL: reads sandbox positions"}
    }
  }
}
```

`input_schema` должна точно совпадать с обнаруженной `inputSchema`, аргументы
проверяются по JSON Schema без загрузки внешних `$ref`. `evidence` — непустой
словарь JSON Pointer → точное значение из обнаруженного определения инструмента
(описание, свойство, enum и т. п.). Это запись ручной проверки назначения,
счёта, контракта и единиц оператором, а не автоматическое распознавание смысла.
Любое изменение схемы требует повторной проверки. Для вызова чтения дополнительно
обязателен `annotations.readOnlyHint: true`; без него инструмент не вызывается.
Эта аннотация сама по себе не доказывает безопасность: нужны проверка оператора
и токен только для чтения.

Результат должен быть `structuredContent` либо одним JSON-блоком текста.
`result_path` выбирает часть результата (пустая строка — весь результат).
Необязательное `fields` переименовывает поля через JSON Pointer:
`{"id": "/uid", "figi": "/figi", ...}`. Для массива оно применяется к каждой
строке. Числа не преобразуются с потерей точности. Константы и вычисляемые
выражения для заполнения отсутствующих сведений не поддерживаются.

| Операция | Ожидаемый результат после выбора полей |
| --- | --- |
| `accounts` | Массив доступных тестовых счетов. |
| `account` | Объект состояния выбранного счёта: баланс, свободные средства и доступные показатели. |
| `positions` | Массив существующих позиций. |
| `orders` | Массив обычных заявок. |
| `stop_orders` | Массив защитных заявок. |
| `catalog` | Массив `{company_id, company_name, share_id, ticker}`. |
| `future` | `{id, figi, ticker, underlying_share_id, expires_at, lot, basic_asset_size, currency, price_unit, quantity_unit}`. |
| `margin` | `{contract_id, currency, tick_size, tick_value, initial_margin_buy, initial_margin_sell}`. |
| `quote` | `{contract_id, price, price_unit, timestamp}`. |
| `trading_status` | `{contract_id, api_trade_available, buy_available, sell_available}`. |

Первые пять операций показывают прочитанные данные, не выполняя бухгалтерскую
сверку. Проверьте одинаковый account ID в аргументах всех запросов счёта;
запросы контракта должны относиться к выбранному фьючерсу. Пустой массив означает
полученный пустой список, `unavailable` — отсутствие подтверждённого чтения.
Ошибки одной операции не подавляют остальные. Ответы сохраняются вместе с
выбранными данными, имена инструментов и схемы — отдельно.

Каталог сохраняет разные идентичности эмитента и акции, конкретный фьючерс
ссылается на ID базовой акции. Не подставляйте тикер акции вместо ID компании.
Время задаётся ISO 8601 с часовым поясом. Цена — в `points`, количество заявки —
в `lots`. Денежные величины и размеры — десятичные строки либо объекты
`{units, nano}`; денежные объекты дополнительно содержат `currency`. Цена и шаг
в пунктах не могут быть денежным объектом с валютой. Лотность, шаг, стоимость
шага, размер базового актива и обеспечение должны быть положительными.
Подтверждается только `lot=1`: один лот заявки равен одному контракту;
размер базового актива не умножается на стоимость пункта повторно.

Если сервер не возвращает единицы, issuer/share связи или другие обязательные
сведения, они остаются неподтверждёнными. Не дописывайте их как данные площадки.
Другой API автоматически не включается: его подключение потребует отдельного
решения и реализации. Полный Invest API не доказывает наличие этих возможностей
в MCP.

## Защита, готовность и секреты

Допустимы привязки `create_order`, `create_sl`, `create_tp`, `read_stops`,
`cancel_stop`. Их схемы, аргументы и свидетельства проверяются, но **ни один из
этих инструментов не вызывается**, включая `read_stops` (фактическое чтение —
через `stop_orders`). Для SL и TP проверьте разные типы стопа в схеме; одна общая
фраза «стоп-заявки» не подтверждает оба типа. Результат проверки —
`schema_reviewed_not_exercised`, а не доказанное исполнение защиты.
OCO, reduce-only и атомарный вход всегда `not_verified` в этом срезе.

`contract.confirmed` проверяет связи идентификаторов, валюту, лотность, точность
шага, положительность параметров, экспирацию, котировку не старше 60 секунд
(будущая отметка отклоняется) и разрешение покупки/продажи через API.
`data_confirmed` требует также чтения всех операций таблицы; код выхода 0 означает
только эту диагностику. Это не допуск к торговле: `execution_enabled` всегда false,
риск, комиссии, жизненный цикл защиты и восстановление ещё не реализованы.

`source: "sandbox_mcp"` означает ответ удалённого sandbox MCP. Контрольные
проверки используют `source: "control"` и вымышленные данные; они не подтверждают
ответы площадки. Sandbox сам эмулирует торговлю и не подтверждает реальную ликвидность.

Токен, заголовки и поля авторизации маскируются перед записью и выводом,
исключения сервера не печатаются. Архив публикаций и входы моделей команда
не использует. На время CLI-команды отключены логи SDK, способные печатать сырые
ответы сервера; прежний уровень логирования восстанавливается при выходе.
Отчёт содержит финансовые данные счёта: храните `.local` локально
и не отправляйте отчёты в модели автоматически.

## Приёмка

```console
.venv\Scripts\python -m unittest discover -s tests -p test_sandbox.py -v
.venv\Scripts\python -m mypy --strict news_futures tests
.venv\Scripts\python -m unittest discover -s tests -v
```

Контрольные тесты покрывают корректный каталог/контракт, MCP-пагинацию, чтение
структурированного и текстового JSON, отсутствие операций, дрейф схем, неверные
аргументы, запрет вызовов записи, единицы/валюты/лотность, котировку и доступность,
редакцию секретов и отказ от другого контура. Транспорт SDK проверяется через
HTTP MockTransport с настоящим MCP initialize и tools/list.

Отдельная живая приёмка: с локальным токеном получить `tools.json`, проверить
привязки и повторить команду в новом каталоге. Сохранённый `diagnostics.json`
должен содержать фактические данные счёта, каталога, контракта и явные ограничения
MCP. Отсутствие токена или обязательных полей не позволяет отметить эти критерии
как подтверждённые площадкой.
