# Непрерывная обработка новостей

## Где менять бизнес-логику

| Участок | Модуль |
| --- | --- |
| Запуск, обработка очереди и передача одобренного предложения исполнителю | [runtime.py](../news_futures/application/runtime.py) |
| Профиль запуска и фиксация настроек моделей и каталога для редакции | [application/config.py](../news_futures/application/config.py) |
| Маршрутизация, сопоставление события, снимок и разбор с критиком | [application/workflow.py](../news_futures/application/workflow.py) |
| Результаты обработки, статус счёта и отчёт CLI | [application/records.py](../news_futures/application/records.py) |
| Чтение состояния счёта и контракты брокера | [trading/account.py](../news_futures/trading/account.py), [trading/broker.py](../news_futures/trading/broker.py) |
| Допуск по риску и исполнение в песочнице | [trading/risk.py](../news_futures/trading/risk.py), [trading/executor.py](../news_futures/trading/executor.py) |
| Намерения, ответы брокера и подтверждённые исполнения | [trading/journal.py](../news_futures/trading/journal.py) |

Граф владеет состоянием анализа редакции. Его идентификатор и снимок данных
для разбора позволяют возобновить работу с той же контрольной точки. После
одобрения критика приложение заново проверяет предложение и состояние счёта.
Исполнитель записывает намерение до отправки заявки. Если ответ потерян,
сверка читает журнал и состояние брокера. Конфликт активных циклов на одном
счёте блокирует исполнение. Панель читает эти же записи для трассы решения.

После перехода на структуру с подпакетами используйте прежний `data_dir`.
Приложение читает существующий архив и контрольные точки. Ссылки профиля на
прежние пути встроенных настроек моделей и источников разрешаются автоматически.

## Запуск

Выполняйте команды PowerShell из корня репозитория с Python 3.11.
Приложение запускается командой `python -m news_futures` из этого каталога.
Для нового окружения выполните:

```powershell
py -3.11 -m venv .venv
.venv\Scripts\python -m pip install -r requirements-telegram.txt -r requirements-openrouter.txt -r requirements-sandbox.txt
.venv\Scripts\python -m pip check
New-Item -ItemType Directory -Force .local | Out-Null
if (-not (Test-Path .local/credentials.toml)) {
    Copy-Item credentials.example.toml .local/credentials.toml -ErrorAction Stop
}
```

Если Launcher не видит Python 3.11, в первой команде укажите полный путь к
`python.exe` этой версии. Заполните секции `[telegram]`,
`[openrouter]` и `[sandbox]` по шаблону. Подпишитесь в используемом аккаунте
на `@markettwits` и `@rbc_news`. Создайте `.local/sandbox-settings.json`
по [инструкции диагностики](sandbox.md). Затем авторизуйтесь локально
и выполните диагностику в новом каталоге.

```powershell
.venv\Scripts\python -m news_futures telegram-login
.venv\Scripts\python -m news_futures sandbox-diagnostics .local/sandbox-report --config .local/sandbox-settings.json
```

Диагностика читает MCP и готовит каталог. `serve` отдельно проверяет подключение
к Sandbox REST перед обработкой новостей. В каталоге из отчёта найдите компанию
по совпадению `share_id` с `operations.future.data.underlying_share_id`.

Сохраните `.local/runtime.json`. Пути внутри файла отсчитываются от его
каталога. В `catalog` укажите отчёт `diagnostics.json` со списком компаний
и UID акций из [диагностики песочницы](sandbox.md). Ключи `contracts` —
UID фьючерсов, значения — ID компаний из каталога. Для каждого фьючерса
при запуске проверяется UID базовой акции. Используйте открытый sandbox-счёт
с положительной стоимостью портфеля.

```json
{
  "data_dir": "runtime",
  "catalog": "sandbox-report/diagnostics.json",
  "account_id": "SANDBOX_ACCOUNT_ID",
  "contracts": {"FUTURE_UID": "COMPANY_ID"}
}
```

По умолчанию используются MarketTwits и РБК, внешняя сессия
`telegram-login` и настройки моделей из пакета. Чтобы изменить их, скопируйте
`news_futures/adapters/telegram-sources.json` и `news_futures/agents/openrouter-models.json`
в `.local/` и добавьте в `runtime.json` поля `"sources": "telegram-sources.json"`
и `"review": "openrouter-models.json"`. В первом файле добавьте имя
разрешённого канала без `@` в `channels`. Аккаунт должен быть подписан на канал.
Во втором замените, например, `critic.model` на точный ID модели OpenRouter
с поддержкой JSON Schema. Аналитик и критик настраиваются независимо.
Для привязки к компаниям и сопоставления событий используются поля `jev` и `matcher` и шаблоны
`news_futures/agents/jev-model.json` и `news_futures/agents/event-model.json` соответственно.
При необходимости укажите `session` и `ca_file`. На каждую редакцию создаётся
снимок моделей и каталога. Изменение модельных файлов применяется со следующей
редакции. Изменения общей конфигурации и списка каналов требуют перезапуска.

```powershell
.venv\Scripts\python -m news_futures serve .local/runtime.json
.venv\Scripts\python -m news_futures runtime-status .local/runtime.json
.venv\Scripts\python -m news_futures runtime-status .local/runtime.json --decision DECISION_ID
```

`serve --once` читает доступные изменения и обрабатывает очередь перед
выходом. Текстовая история при первом подключении сохраняется в архиве
публикаций. Дословная перепечатка из этой истории пропускается перед анализом
компании. Модели получают текст текущей редакции и связанные материалы
из архива событий, включая доступные текстовые подписи. Признак
непрочитанного медиа сохраняется. Цена, таймер и исполнения сами по себе
не вызывают модели. Для чтения всех исходников используйте
`publications --database .local/runtime/publications.sqlite3`.

`runtime-status` показывает время последней проверки источников и брокера,
позицию, подтверждение защиты, задержку от получения новости и последние
результаты. `--decision` принимает `decision_id` из архива событий или
`revision` из списка результатов. По нему доступны публикация, маршрутизация,
событие, вход анализа, разбор критика и журнал связанного торгового цикла.
В отчёте по решению смотрите `result.status` и `result.reason` для причины
пропуска или отказа, `result.execution` и `trades` для исполнения. Общий отчёт
без `--decision` показывает `broker.position` и `broker.protection` по последней
сверке счёта.
Путь к базе событий для диагностических команд —
`.local/runtime/events.sqlite3`.

По умолчанию действует `observation`. Этот режим использует только операции
чтения. Для выбора песочницы добавьте `"mode": "sandbox"` в конфигурацию.
Для всех запусков на одном счёте используйте тот же каталог данных. Записанный результат
по редакции остаётся в исходном режиме. Сверка песочницы работает независимо
от новостей. Новостной выход требует согласия критика, свежих брокерских
данных и идентификатора конкретного цикла позиции.

Приложение блокирует автономный вход в Т‑Банке с причиной
`autonomous_protection_unavailable`. Адаптер использует два независимых
стопа, и защита от двойного исполнения для них не подтверждена. Контрольные
тесты исполняют полный цикл через брокера с подменённым транспортом.
Отдельный ручной сценарий описан в [приёмке песочницы](sandbox-execution.md).

## Остановка и восстановление

Остановите `serve` через Ctrl+C и запустите его снова с тем же `data_dir`.
Остановка сохраняет очередь и контрольные точки в `checkpoints.sqlite3`.
Приложение дожидается уже начатой обработки. Подтверждённые SL/TP остаются
на платформе. Каталог данных используется одним `serve` за раз.

При запуске приложение сверяет позиции, обычные и защитные заявки до продолжения
очереди. Если результат запроса неизвестен, `runtime-status` показывает
`processing`, состояние сверки и журнал торгового цикла. Исполнитель продолжает
сверку по сохранённым идентификаторам. Если закрытие согласовано, но брокерские
операции ещё не начались, приложение повторно проверяет предложение после
восстановления источников. При неподтверждённой защите торговля
остаётся заблокированной до установления состояния брокера. У Т‑Банка без ответа
на установку стопа принадлежность заявки может остаться неподтверждённой.

Telegram продолжает чтение с сохранённого курсора. Если журнал обновлений
истёк, приложение сохраняет доступные сообщения и последние редакции и отмечает
потерянные промежуточные редакции и удалённые сообщения в `runtime-status`.
Начальная история остаётся контекстом. Пропущенная публикация старше 15 минут
может привести к переоценке открытой позиции по свежему рынку. Для нового входа
проверяются исходное время публикации и срок действия предложения.

Завершённые узлы анализа восстанавливаются из контрольных точек. Незавершённый
вызов модели может повториться. При изменении позиции или устаревшем рыночном
снимке прерванный анализ продолжится с новым снимком. Журналы предыдущих
попыток доступны из отчёта решения. При смене режима, счёта или
контрактов незавершённое вычисление из прежней конфигурации не отправляет заявки.

### Локальная панель оператора

Соберите интерфейс и запустите панель по [инструкции из README](../README.md#локальная-панель-оператора).
В разделе «Тикеры» введите тикер акции,
тикер фьючерса или UID контракта. Выбор серии меняет позиции, заявки и решения,
а публикации и редакции остаются в контексте компании. Для прошлых серий
панель использует сохранённые тикеры из сверки и архивного каталога.
Когда архив содержит только UID, поиск и фильтр работают по UID.
Другие материалы того же события видны в карточке. Ссылка на трассу
доступна для редакций с сохранённой привязкой к компании.

«Решения» показывает публикации с сохранённой привязкой, в том числе
пропущенные и отклонённые. Период относится к времени записи решения,
если оно сохранено. Раскройте шаг трассы, чтобы увидеть сохранённые вход,
ответ и источники. Для старых записей время сохранения файла помечено
отдельно от времени шага. Панель показывает, когда детали отсутствуют.

В «Сделках» видны заявки и подтверждённые исполнения. Средние цены показаны
в пунктах, объёмы в лотах. Торговый цикл связан с трассами входа и новостного
выхода, если они есть. Для ручного и защитного выхода основание и сверка
доступны в журнале цикла.

Пауза блокирует новые входы и сохраняется между запусками. Новости и сопровождение
открытой позиции продолжаются. В песочнице кнопка закрытия появляется для
подтверждённой позиции приложения. После подтверждения обработчик заново сверяет
её объём и защиту перед отправкой заявки.

Для сквозного теста на Windows задайте путь к установленному Chromium
и соберите интерфейс. Тесты используют локальный архив и управляемого брокера.

```powershell
npm.cmd --prefix news_futures/operator/web ci
npm.cmd --prefix news_futures/operator/web run build
$env:OPERATOR_TEST_CHROME = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
.venv\Scripts\python -m unittest discover -s tests/operator_panel -v
```

Для нового типа источника реализуйте получение и восстановление курсора в
адаптере. Преобразуйте входные данные в `Publication` из
`news_futures.news.publications`: задайте устойчивые `source` и `external_id`,
ссылку, текст, время публикации и получения с часовым поясом. Для редакции
передайте `edited_at` и `change="edit"`, для удаления `change="delete"`.
Сохраняйте пакет через `Archive.save_batch` с положительным монотонным
курсором источника и `historical=True` для начальной истории. Архив сохраняет
редакции и курсор одной транзакцией. Подключение транспорта нового типа
выполняется в сборке приложения. `Runtime.process` принимает сохранённые
редакции через общий архив, поэтому узлы графа от транспорта не зависят.
