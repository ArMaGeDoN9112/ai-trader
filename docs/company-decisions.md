# Решение по компании и открытой позиции

После [сопоставления публикации с событием](events.md) возьмите
`decision_id` из текущего решения с непустым `analysis_company_ids`.
Один запуск рассматривает всех затронутых разрешённых кандидатов вместе.
Перепечатки и заменённые решения анализ не запускают.

```powershell
.venv\Scripts\python -m news_futures analyze-event 42 --snapshot .local/snapshot.json --directory .local/decision-42
.venv\Scripts\python -m news_futures show .local/decision-42
```

Укажите `--database`, если для событий используется другой файл SQLite.
Без `--directory` результат сохраняется в новом каталоге
`.local/news-futures-07`. Настройки аналитика и критика берутся из
`openrouter-models.json` или файла `--config`. Используются
[зависимости и ключ OpenRouter](openrouter.md).

## Снимок рынка и счёта

Перед запуском подготовьте JSON по текущим данным чтения рынка и счёта.
Тикет 07 принимает снимок как вход цикла наблюдения. Отметки времени включают
часовой пояс. На старте цикла снимки счёта и рынка кандидатов должны быть
не старше пяти минут. Время из будущего отклоняется. `allowed_for_entry` задаётся
оператором для конкретного контракта. Идентификаторы компаний должны совпадать
с каталогом, использованным при привязке новостей. Используйте локальный
идентификатор счёта. Ключи и сессии в снимок не включаются.

```json
{
  "account": {
    "id": "sandbox-account",
    "observed_at": "2026-11-08T11:00:00+03:00",
    "currency": "RUB",
    "equity": 100000.0,
    "available_margin": 90000.0
  },
  "position": null,
  "instruments": [
    {
      "company_id": "COMPANY_ID",
      "company_name": "Название компании",
      "share_id": "SHARE_ID",
      "contract_id": "FUTURE_ID",
      "allowed_for_entry": true,
      "market": {
        "observed_at": "2026-11-08T11:00:00+03:00",
        "last_price": 300.0
      }
    }
  ]
}
```

Для открытой позиции заполните `position` полями `id`, `contract_id`,
`side` (`long` или `short`) и целым положительным `quantity`. Включите её
контракт в `instruments`, даже если новые входы по нему запрещены. `id` должен
обозначать конкретный вход и меняться при следующем открытии того же контракта.
До анализа зарегистрируйте исходную причину в той же базе событий.

```powershell
.venv\Scripts\python -m news_futures entry-reason .local/entry-reason.json
```

```json
{
  "account_id": "sandbox-account",
  "position_id": "POSITION_ID",
  "contract_id": "FUTURE_ID",
  "reason": "Исходное основание открытия позиции"
}
```

Повторная запись той же причины допустима. Попытка изменить сохранённую
запись отклоняется. При отсутствии исходной причины цикл завершается до
обращения к моделям.

## Результат

В `context.json` сохраняются редакция, сведения о событии, исходные ссылки
и переданный моделям снимок. Для связанных новостей действует бюджет 40 000
байт сериализованных записей. Приоритет у свежих существенных материалов.
`omitted_related_news_count` показывает число пропусков. Полные исходники
доступны через `events --company COMPANY_ID`. Текст поступившей публикации и
сохранённая причина входа передаются целиком.

Аналитик сравнивает кандидатов, ссылается на редакции и цитирует тексты.
Программа сверяет цитаты, а критик проверяет, подтверждают ли они влияние
на компанию и выбранное действие. Критик может подтвердить связь с удерживаемой
компанией по исходному тексту, даже если маршрутизатор её пропустил.
После возражения разрешён один пересмотр. Если решение о событии заменили
во время анализа, согласованное предложение остаётся в журнале вызовов
и не передаётся на независимые проверки.
В `trace.json` видны выводы и возражения каждой модели. `no_action` означает
согласованный пропуск или удержание. `approved_for_checks` означает
согласованное предложение входа либо полного закрытия, которое ждёт
независимых проверок. Число контрактов, сверка свежести перед заявкой и
исполнение относятся к последующим тикетам.

## Проверка приёмки

```powershell
.venv\Scripts\python -m unittest discover -s tests -p test_company_decisions.py -v
```

Тесты проходят через CLI и контролируемый HTTP-транспорт OpenRouter.
Проверяются сравнение кандидатов, пропуск при недостаточных доказательствах,
удержание, опровержение причины входа, новость по другому инструменту и
явное ограничение истории.
